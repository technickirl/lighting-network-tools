Luminex Commission – Quick User Guide

27 November 2026 · version 2.1.1 · Nick Malbon and Alex Mead

What it does

Luminex Commission is one app, run on a laptop on the wired show network, that finds every LumiNode, LumiCore and GigaCore on the network and lets you address, name, reset and configure them, read and set RDM fixtures through the nodes, watch the sACN on the network and send a little of its own for testing. It serves its own page in your browser at http://localhost:3800; nothing is installed and no internet is needed.

ViewUse it for
DevicesThree parts. All devices: the list, with Configure on each node; nothing here can re-address the rig. Address & reset: commissioning (numbering plan, addresses, names, LED, factory reset). Groups: GigaCore Gen1 groups (VLANs).

Getting started

  1. Download the release for your laptop: LuminexCommission-<version>-macos-app (any Mac: an app with a menu bar icon), -macos-arm64 or -macos-x64 (Apple silicon or Intel Mac, in a Terminal window) or -win-x64.exe. Mac builds come as a zip; unzip it.

  2. Give the laptop a static address on the show network, on the same first two octets as the rig (for example 192.168.0.200/16), on the wired port.

  3. Start it. Mac: the first time, run xattr -d com.apple.quarantine <file> or use System Settings → Privacy & Security → Open Anyway, then double-click. The Mac app asks once to find devices on your local network: choose Allow, or the scan finds nothing. It has no window: quit it from its menu bar icon, where Show Log is too. Windows: double-click, and allow it through the firewall when asked.

  4. The page opens at http://localhost:3800 and scans straight away. Close any other Art-Net software first: RDM needs UDP port 6454.

The device list

Devices are found by mDNS (_luminex._tcp) and listed with model, name, address, serial and firmware, plus what each is cabled to (read from LLDP). The scan reruns by itself when the laptop gains an address, such as a cable being plugged in; press Scan any time.

  • Not listed? Use Add by address under the list. It works for LumiNode, LumiCore and GigaCore Gen2, not Gen1.

  • Red notes flag devices sharing an address and a device on the laptop's own address (unreachable until you move the laptop).

  • Passwords: the app tries none, then admin with a blank password, then asks. A password you type is kept in memory for that device only, never saved.

  • Identify on a row flashes the device.

Addressing and naming (Devices, Address & reset)

Every address is <network>.<third octet>.<n>, where you pick the first two octets in the Network box and a third octet per device type in the numbering table.

  1. Simple Numbering: One 4th octet per batch (no cabling needed: every ticked device gets the same last octet on its type's third octet, then it steps on for the next batch)

  2. Following the cabling, set each device type to Paired or Sequence. Paired: a switch and the node cabled to it share a last octet (switch .2.1 + node .3.1, then .2.2 + .3.2), numbered along the chain. Sequence: the type counts 1, 2, 3 on its own third octet. Reorder with ↑/↓ or drag.

  3. Check the Next address column. Devices already in range keep their number; tick Renumber all in cabling order to start again.

  4. Under Apply, tick what to send (addresses, device names, LED, web password off) and the devices to include. Every new device starts ticked.

  5. Apply settings. Nodes move first, then switches; each change is confirmed when the device reappears in mDNS at the new address, then names and LED are sent and read back.

Devices sharing one address (hire stock often arrives that way) are flagged in red; Fix duplicates moves each one to its planned address over IPv6 link-local, without touching anything else. GigaCore Gen1 has no IPv6, so connect those one at a time. Save numbering keeps the table in a file per rig.

Configuring a node

Configure on a node's row opens it on the Node tab of the same page. It follows the node if its address changes and locks its write buttons while a job runs on it.

The chips along the top of the Node tab are every LumiNode in the device list, with the open one highlighted. Click a chip to switch to that node; you stay on the same tab (RDM, say). A chip is disabled, with the reason in its tooltip, for a node this computer cannot reach.

TabWhat you do there
DeviceWhat the node is, Identify and Reboot, and its name, address, mask and gateway; an address change runs as a confirmed job. The node opens here.
Quick SetupSet one sACN universe per DMX port and apply all ports in one step (reroute mode).
ProfilesRecall or save a profile on the node.
RDMTick RDM on per port, read and set fixtures (next section).
AdvancedProcess blocks (merge, backup, crossfade), the sACN, Art-Net and DMX IOs feeding them, the live state of each DMX port, and startup buffers.

Quick Setup is the fastest way to patch a node: each DMX port gets one universe straight through. The tab shows a field per port, filled with the universe it takes now; type the universes you want and press Apply, which sends at once. Each port you fill has its process block rebuilt as a simple reroute (input to port, named Port 1 U101 and so on), so any merge, backup or startup buffer on that block is replaced; leave a field blank to leave that port alone. The protocol stays what the port already uses, sACN or Art-Net (the label above the field says which), and a new sACN input comes in at priority 100.

A node that has changed address may show its active profile as None afterwards; its blocks and IOs are unchanged.

RDM

RDM runs from the laptop over Art-Net through each node, and works on ports fed by sACN with no change to the port.

  1. On the node's RDM tab, tick RDM on a port and confirm in the page (untick to turn it off). DMX keeps flowing, though some older fixtures flicker during discovery.

  2. Wait for Searching… n found to settle (about 10 to 15 s for a line of 15 to 20 fixtures). The port is then read and shown as tiles; TABLE switches to a table.

  3. Fixtures that were still powering up are missed: press Rediscover to search again.

  • Tap a tile to identify that fixture; double-tap for its fixture page (patch, hours, sensors and every setting it supports). ID OFF stops all identifies on the port.

  • Tap the address on a tile for the keypad: type, then SEND & NEXT walks down the line. Next = this + sets the step (CH follows each fixture's footprint).

  • Edit or the fixture page sets address, label and personality. Every SET is read back, and clashes or a run past 512 show in red.

  • Tick tiles on one port to act on them together: ID ON / ID OFF, PERSONALITY… and SETTING… (one model only), READDRESS… and FACTORY RESET… (warning first). They run one fixture after another, and each tile shows how it went; STOP ends the run after the current fixture.

  • READDRESS… respaces the ticked fixtures in their current patch order, for example after a mode change. Choose a new mode for all of them (one model only; mixed models keep their own), from a start address and every N channels, or leave every empty to pack them by footprint. The line underneath shows every move (1→1 · 11→21) and warns about unticked fixtures the new patch would overlap; the button stays grey if the spacing is too small or the patch would run past 512.

  • Factory reset (fixture page or ticked tiles) shows a warning first. With KEEP ADDRESS on (the default) each fixture is reset and then put back on its own DMX address; the mode goes back to factory, so check the tiles for clashes and use READDRESS… if the footprint changed. If the address cannot be read first, nothing is sent.

  • The Fixtures view reads every node with RDM on and lists all fixtures by address; Only fixtures with a problem filters to clashes and Export CSV saves the patch with UIDs.

sACN: View

Shows what is arriving on each sACN universe. It only listens: nothing in this view changes a level or a device.

  • Type the universes to listen to, for example 1-8, 33, and press Listen. The list is remembered. Universes a console announces are added by themselves.

  • Each universe is a chip with a dot: green for one source, grey for nothing arriving, amber for two sources at the same priority (usually a mistake).

  • Click a chip for its source, frame rate and all 512 levels, live. On the wire is what a node would output (the highest priority, and the higher level where sources share it); click a source to see that source alone. Levels in % switches from 0-255.

  • A source that stops stays listed as lost for 30 seconds.

sACN: Control

Makes the laptop a small sACN source, for testing a rig without a console. Nothing is sent until you press Start output, and it never starts by itself. While it is sending, every node listening to those universes puts the levels on its DMX outputs, so treat Start like bringing up a fader on a desk.

  1. Choose the network connection to send From (the wired show port, not Wi-Fi). Priority is 100 unless you change it.

  2. Each universe in the output is a chip with a tick box: ticked universes are sent, unticked ones are left out with their patch and levels kept. Select all and Deselect all do them all; Add universe adds an empty one, sent at zero. Click a chip's name to show only its fixtures.

  3. On Fixtures, add fixtures to the patch: a name, a profile, universe, address and how many in a row. Or use Patch on a fixture in the Fixtures view, which takes its universe, address and channels from RDM. Patch all there has a button per universe that patches every fixture read on it and says what it did. A fixture already in the patch is left alone, and a profile is only made when none fits.

  4. Press Start output. The bar turns red while sending. Stop output tells the nodes the source has gone, so they return to their other sources at once.

  • Each fixture is a tile with its dimmer, Off, Full, Highlight and Remove; More shows its other channels.

  • Highlight fades the fixture up over half a second so you can find it on the rig (dimmer 50%, red, green and blue full, cyan, magenta and yellow at zero); press it again to fade back to where it was.

  • Click fixture names to select several. The one at the lowest address becomes the MASTER: its faders and buttons move all of them. Starting from … select every … picks along the patch (from 1 every 2 is the odd ones), and Remove selected takes the selected fixtures off the patch at once.

  • Channels is all 512 channels of any universe: click (or Shift-click a range) to select, then use the fader or 0 / 50% / Full.

  • Profiles lists the fixture types. Nine plain ones are built in; New profile or Copy opens the editor, where each channel has a name, a type, a default level and a highlight level. Tick Fine on the channel after a coarse one to make the two a 16-bit pair: one fader on the tile, shown in percent. Pan and tilt default to 128, so a moving light starts centred. Export and Import move a profile between laptops as a file.

  • If a console is sending the same universe, a banner names it and says who wins. Clear all levels puts everything back to zero (fixtures to their defaults).

Factory reset (nodes and switches)

For RDM fixtures, see RDM above. Factory reset in Address & reset resets every ticked device at once, with no confirmation pop-up, so check the ticks first.

  • Keep IP address on reset leaves each device on its current address. Without it a device returns to its factory default address, which differs between devices.

  • Keep LumiNode profiles keeps the nodes' stored profiles.

  • A reset counts as done when the same device (matched by serial) is seen to restart and reappears in mDNS. Expect 70 to 90 s. Not sent: it never reached the device.

  • Afterwards devices have their default names, and nodes are on the factory profile Output ArtNet 0-11: no sACN until you recall an sACN profile.

Using it from an iPad

Other devices (top of the right-hand column) lets an iPad or second laptop on the network use the app. It is on every time the app starts.

  1. Note the address it lists (for example http://192.168.1.201:3800) and the six-digit PIN, shown only on the laptop.

  2. Open that address on the iPad and type the PIN. It stays signed in for 12 hours.

  3. Set a PIN saves one PIN on the laptop, so it stays the same from show to show. New PIN signs every device out; Turn off closes access.

A signed-in device can do everything the laptop can, resets included, so keep the PIN to the crew running the job. Access listens on every network the laptop is on, Wi-Fi too: turn it off on a network you don't trust. RDM state is shared, so fixtures read on the laptop are already on the iPad.

A device is missingIt may share the laptop's address (red note), or mDNS is blocked: use Add by address.
Address change ends Not seen afterwardsThe change may have worked but mDNS can't see the device; Scan again or check it at the new address.
A row or a Configure button says Another device answeredThe device at that address is not the one listed. Nothing was sent: Scan and try again.
RDM tab shows only overheard fixturesAnother program holds UDP 6454; close it and reopen the tab.
Fixtures overlap after a factory resetThe reset kept the addresses but put each fixture back on its factory mode, which can have a different footprint: tick them and use READDRESS… to set the mode and respace them in one go.
RDM finds fewer fixtures than are on the lineFixtures were booting when RDM went on: Rediscover.
No sACN after a resetNodes come back on the factory profile, Art-Net 0-11: recall an sACN profile. Quick Setup keeps each port's protocol, so it would stay on Art-Net.
sACN View shows Nothing arrivingThe laptop must be on the sACN network (and in the same group or VLAN as the console). Not every console announces its universes, so type them.
sACN Control is sending but fixtures don't moveCheck From is the wired show port, the node's port is on that universe, and no console is sending it at a higher priority (the banner says).
Configure button greyed outHover for the reason: a switch, a device in a running job, or an address no adapter can reach.
Page looks out of date after an updateIt reloads itself on reconnect; otherwise hard-refresh (Ctrl/Cmd+Shift+R).

Every device request and reply is logged with a timestamp in the app's window; send that log with any fault report.
